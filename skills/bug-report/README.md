\# bug-report



\## 왜 만들었나

여러 명이 각자 AI 코딩 도구로 개발하면 버그를 기록하는 방식이 사람마다 달라질 수 있다.

누가 기록해도 같은 양식으로 남고, 기록을 통해 이슈 관리가 잘 되도록 표준화하려고 만들었다.



\## 무엇을 하나

\- 등록: 버그가 발생하면 시간·작업자(GitHub 사용자명)·브랜치·커밋을 직접 확인해 채우고, 재현 절차와 기대 결과는 사용자에게 물어 GitHub Issue(bug 라벨)로 등록한다. 등록 전에 대상 저장소와 초안을 보여 주고 확인받는다.

\- 해결: 조치가 끝나면 같은 이슈에 원인(확인된 것과 추정 구분)·수정 방안·수정 후 결과를 댓글로 남기고, 확인받은 뒤 닫는다.



\## 사용 예

\- "버그 있어, 이슈 기록해줘" → 정보를 모아 이슈 초안을 보여 주고, 확인받은 뒤 등록

\- "이슈 해결 기록해줘" → 해결 댓글 초안을 보여 주고, 확인받은 뒤 등록하고 닫기



\## 시험 결과 (연습 저장소 bug-report-practice)

| 확인 항목 | 결과 |

|---|---|

| 자동 호출 | 통과: 스킬 이름 없이 "버그 기록해줘"로 호출됨 |

| 직접 확인 (시간·작업자·브랜치) | 통과: 묻지 않고 직접 채움, 중복 이슈와 라벨도 확인 |

| 추측 금지 | 통과: 오타를 찾지 못하자 지어내지 않고 되물음 |

| 등록 전 확인 | 통과 |

| 해결 기록과 닫기 | 통과 |



\## 시험 중 발견해 고친 점

\- Claude가 커밋 메시지에 "Closes #1"을 넣었다. 이 커밋이 push되면 이슈가 자동으로 닫혀서 "확인 없이 닫지 않는다" 규칙을 우회하게 된다. 커밋 메시지에는 Refs #번호만 쓰도록 규칙을 추가했다.

\- 개인 스킬은 모든 프로젝트에서 작동하므로, 엉뚱한 저장소에 등록되지 않도록 등록 전 확인 화면에 대상 저장소를 표시하도록 했다.
